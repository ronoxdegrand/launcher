# High-risk integration findings

Evidence reviewed 2026-10-26. “API supported” is not a claim that the Galaxy S23 has passed a device test. No Samsung handset was attached at implementation start. Runtime results and actual device availability belong in VALIDATION.md.

| Integration | Finding and foundation decision | Remaining proof / fallback |
|---|---|---|
| Default Home and app discovery | Public HOME/DEFAULT manifest registration, RoleManager HOME request, LauncherApps discovery and launch. Separate Settings activity owns the installed launcher icon. | Select Home through the real role dialog on the S23; verify Home, Recents and gesture navigation. |
| Widget hosting | AppWidgetHost with a stable host ID, start/stop listening tied to the activity, user-approved binding, provider configuration, size options, ID cleanup and local placement persistence. Widget dimensions reported by provider info are pixels; options sent to providers are dp. | Runtime fixture tests plus S23 Samsung/Google widgets. Providers can impose their own minimum dimensions and consume long presses; Manage home items remains available. |
| Widget gesture interception | One parent canvas intercepts directional horizontal drags even when a child asks to consume them. Vertically locked gestures remain with the child. Rendering uses ordinary Views and OverScroller; invalidation runs only during motion. | Test vertically scrolling collection widgets and diagonals on S23. Horizontal widget gestures are intentionally unavailable by product design. |
| Samsung native app pairs | Samsung documents saving pairs from its split-screen UI, but that documentation does not establish an API contract for delivery to an arbitrary third-party launcher. **Unverified**, not proven impossible. | While this launcher is default, check whether Samsung offers Save to Home and whether it delivers a standard pin-shortcut request. Standard pinned shortcuts are implemented; Samsung delivery still needs device proof. Skip pairs if One UI does not expose them; no hidden APIs, split-screen manager or Edge workaround. |
| Assistant prefilled query | ACTION_ASSIST is public, but resolving a handler does not prove that the configured assistant consumes arbitrary query text. There is no verified universal assistant-query contract in this project. | Test an explicit harmless typed phrase with the S23's selected assistant. Hide/omit Ask Assistant if text is ignored or no supported path exists. Do not silently substitute web search or a custom assistant. |
| Gesture navigation animation parity | Standard Home works through public APIs. AOSP Quickstep uses a SystemUI/overview service connection; reproducing One UI's privileged integration is outside this APK's supported contract. | Check gesture Home/Recents behavior and animation quality on S23. Accept system-provided transitions; no accessibility service or privileged recents replacement. |
| Live activity deduplication | Android API 36 introduced system-set FLAG_PROMOTED_ONGOING, readable by NotificationListenerService. This provides a supported signal on applicable systems, not a universal Samsung live-activity detector and not an API 34 guarantee. | Filter only when a reliable system flag is present; otherwise preserve notifications. Never infer duplication from ongoing status alone. The implemented workspace filters only this public flag. |
| Notification counts/privacy | Active notification records and message counts are different concepts. Group summaries can duplicate children; redacted/sensitive content can be unavailable. | Define badges as active notification counts with explicit group-summary handling. Test grouped messaging/media/private notifications. Read-only listener must never invoke content/actions or cancellation APIs. |
| UsageStats retention | Public UsageStats APIs require user-authorized usage access. Android documents that raw events survive only a few days; a 14-day hourly history cannot be assumed on first install. | Maintain local foreground-duration summaries incrementally; checkpoint boundaries and avoid double counting. Use aggregate/context fallbacks and deterministic app selection without permission. No tracking service. Access is requested only through an explicit settings action. |
| APK signing and installation | Android verifies signatures; compatible signing identity is required to update an installed package. A stable private release key exists outside the repository; release signing verifies its pinned public certificate. | Before distribution, establish and privately back up a stable release key. The updater validates package, version, signature and download before presenting Android's install consent. No silent install promise. |
