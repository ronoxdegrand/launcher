# Design research and iteration · 0.2.5 · 2026-10-29

The product direction remains a quiet, widget-first Android launcher. Modernity here comes from legible hierarchy, consistent geometry, understandable movement and restrained surfaces. The four-column/seven-row system, horizontal search, top input, native icons, wallpaper-only drawer backdrop, keyboard entry behaviours and read-only notifications remain product constraints.

## Research and decisions

- [Material typography](https://developer.android.com/develop/ui/compose/designsystems/material3#typography) separates headline, title, body and label roles. We use native sans-serif with explicit weight and line height: Settings headline 28/36, search 22/28, notification group 16/24, notification title 14/20, reading body 14/22 and app label 12/16. Metadata is secondary, rather than tiny and faint. App labels reserve the same space so different name lengths cannot move icon centers; larger font settings use a single ellipsized label line rather than clipping the icons.
- [Material layout guidance](https://m2.material.io/design/layout/understanding-layout.html) uses an 8dp rhythm with 4dp refinements. The outer product grid is preserved, while 4dp area insets create 8dp gutters between category cards. Captions align to a 16dp inset. Settings uses 24dp page margins, 48dp minimum action rows and 32dp section spacing. Containment groups related content; it does not put a border around every setting.
- [Android accessibility guidance](https://developer.android.com/guide/topics/ui/accessibility/apps) recommends at least 48dp touch areas. The Home search pill grows from 36dp to 48dp, inside a 52dp affordance band. Settings actions, radio choices, notification text previews and the expanded-category collapse cell meet that height. Existing grid cells remain larger targets. Reading-surface primary and secondary color pairs are measured against the 4.5:1 normal-text threshold in both themes. Arbitrary wallpaper glass is not claimed to have guaranteed contrast; the primary input therefore has a stronger local tonal backing, while Settings and menus use opaque reading surfaces.
- [Material's motion physics](https://m3.material.io/styles/motion/overview/how-it-works) distinguishes spatial movement from opacity/color effects and offers a restrained standard scheme for utilitarian products. Our product-tuned critically damped spring preserves position and velocity when retargeted, carries the four dock icons to the search row, and reverses cleanly. It is an analytic implementation, not an import of Material's spring tokens. Short effects use a shared easing curve. Native horizontal fling remains Android's OverScroller. No frame callback remains scheduled when the spring settles or is cancelled. System animation scale, including zero, is honored.
- [AOSP window-blur guidance](https://source.android.com/docs/core/display/window-blurs) recommends genuine cross-window blur, a complementary translucent color, a fallback when blur is disabled, and avoiding radii beyond 150px. The existing 48dp/150px-cap compositor blur stays. A restrained neutral veil, thin outlines and local tonal input improve legibility. There is no screen sampling, wallpaper screenshot service, added permission, or continuous blur calculation.

## Interface changes

Home uses an accessible search pill and smaller badges. Category and folder outlines have real gutters; captions align consistently rather than sitting centered on touching borders. Original icons and four-column centers are retained.

Search retains its full-row footprint, but the 22sp input is the primary visual anchor. The four result icons physically travel from the dock. Their names reveal during that movement. The results strip is a separate drawer layer so the old search container cannot clip it midway through the transition.

Notifications have clearer group/title/body/timestamp roles, quieter counts, more comfortable line spacing and consistent group separation. Explicit expansion fades newly revealed rows while preserving viewport anchoring and native scrolling; incoming events do not start ornamental animation.

Settings is an edge-to-edge reading surface with correct light/dark system bars, aligned rows and section hierarchy. Menus and folder overlays share its readable tonal treatment. Folder opening uses a smaller, subtler scale change and a content-sized overlay, capped for long folders. Editing uses a four-action toolbar and a separate Settings row, with safe navigation-bar space and a frozen Home grid scale. Pressed states use native ripple feedback without additional sound or drawer haptics.

## Iterations and proof

Iteration one passed numerical position checks, but its intermediate screenshot showed the moving icons were clipped by their old parent. Iteration two moves the strip to a dedicated transition layer and verifies visibility as well as position. Visual review also corrected the search background's automatic padding and Settings' wallpaper/system-bar leakage. A real long press exposed an offscreen dock-menu anchor despite its showing flag; menus now use measured bounds within the system-bar/keyboard safe area. Editing reserves navigation space immediately, and folder pivots are assigned after layout.

The measured design runner covers both reading palettes, the Home touch target, shared row geometry, actual intermediate icon visibility, continuous retargeting and settled states. Emulator screenshots and gesture regressions are recorded alongside the release. Galaxy S23/One UI appearance and performance remain device acceptance work; no formal all-wallpapers accessibility or battery claim is made.
